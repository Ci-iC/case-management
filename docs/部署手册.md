# GlobalX 法律事务管理系统 部署手册

> 适用版本：v1.1（PostgreSQL + Docker）
> 当前生产环境：`<<请填写：服务器 IP 或域名>>`（部署方自有云主机 / VPS）· Ubuntu · Node 20.20.2 · pm2 · nginx
> 部署方式：本地打 zip → wget 拉取 → 服务器解压（SSH 在用户网络被 reset，弃用 SCP/`deploy.sh`）

## 〇、先看这里：v1.0 → v1.1 升级关键差异

| 项 | v1.0（已上线） | v1.1（本次） |
|---|---|---|
| 数据库 | SQLite 单文件 `server/data/app.db` | **PostgreSQL 16，跑在 Docker 容器里**，数据存 `./pgdata/` |
| 服务器需装 | Node + pm2 + nginx | 上述 + **Docker + Docker Compose** |
| 启动顺序 | 直接 `pm2 start` | 先启 PG 容器 → 跑 migration → 再 pm2 |
| `.env` 配置 | `DB_FILE=./data/app.db` | `DATABASE_URL=postgres://...` + `PG_*` |
| 文件存储 | `server/data/`（仅放 SQLite + 案件附件） | `server/data/reviews/`（合同）+ `server/data/attachments/`（消息附件）；SQLite 已废弃 |

### ⚠️ 必读两条提醒

1. **本次走全新启动路径**：v1.0 服务器上的所有数据都是测试数据，确认可清空。
   背景知识（仅供了解）：`001_init.js` 是纯建表 migration，不会读老 SQLite `app.db`，所以即使想保留 v1.0 数据也不会自动迁过来——但本次部署前提是数据可丢，不需要操心这个。

2. **`.env.production` 当前还是 v1.0 旧版**（只有 `DB_FILE`），第一次部署 v1.1 前**必须重写**——本文档第二章给出 v1.1 模板。

## 一、服务器前置：首次部署 v1.1 需要装 Docker

如果服务器之前只跑过 v1.0，**只装了 Node**，要先把 Docker 装上。已经装过的跳过本章。

```bash
ssh <<请填写：SSH 用户>>@<<请填写：服务器 IP 或域名>>

# 1) 装 Docker（官方一键脚本，Ubuntu 通用）
curl -fsSL https://get.docker.com | sh

# 2) 启动并设为开机自启
systemctl start docker
systemctl enable docker

# 3) 验证
docker --version          # 应输出 Docker version 24.x 或更新
docker compose version    # 应输出 Docker Compose version v2.x
```

如果国内拉镜像慢，配镜像加速器（在 `/etc/docker/daemon.json` 加 `"registry-mirrors"`，重启 Docker），或在后续 `.env` 里直接用 `POSTGRES_IMAGE=docker.m.daocloud.io/postgres:16-alpine`。

> **2GB 内存提醒**：阿里云轻量 2GB 同时跑 nginx + Express + PG 容器会比较紧（PG 自身约占 100~200MB）。监控用 `free -h` / `docker stats`。如吃紧，给 PG 容器加 `mem_limit: 512m`。

## 二、本地打包

### 2.1 准备 `.env.production`（替换旧版）

打开 `<项目根目录>\case-management\.env.production`，**整个删掉**，按下面 v1.1 模板写（**生产用强密码 / 长随机串，不要直接抄占位符**）：

```env
PORT=4000
JWT_SECRET=<在这里粘贴一段 64 位随机字符串>
NODE_ENV=production

# 首次启动用于 seed 第一个 admin 账号；之后不会重新读取
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<这里写一个强密码，第一次登录后立刻改>
ADMIN_DISPLAY_NAME=系统管理员

# PostgreSQL —— docker-compose.yml 和 Express 共用这一组
PG_DB=case_mgmt
PG_USER=case_mgmt
PG_PASSWORD=<这里写一个强密码，PG 容器和应用共用>
DATABASE_URL=postgres://case_mgmt:<上面那个 PG_PASSWORD>@127.0.0.1:5432/case_mgmt

# 国内服务器拉 docker.io 慢可启用这行
# POSTGRES_IMAGE=docker.m.daocloud.io/postgres:16-alpine

# AI 审核（OpenAI 兼容接口）—— 也可以等部署完进系统设置里改
OPENAI_API_KEY=sk-<生产用 key>
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL_DEFAULT=gpt-4o-mini

UPLOAD_MAX_BYTES=20971520
```

生成 `JWT_SECRET` 的快速方式（PowerShell）：
```powershell
[Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Maximum 256 } | ForEach-Object { [byte]$_ })).ToLower()
```

### 2.2 本地构建前端

```powershell
cd "<项目根目录>\case-management"

# 装好依赖（如果之前没装）
npm install

# 构建生产版前端到 dist/
npm run build
```

生成的 `dist/` 是 Express 静态托管的目标。**dist 必须打进 zip 一起上传**，避免在 2GB 服务器上构建。

### 2.3 打 zip

PowerShell：

```powershell
cd "<项目根目录>\case-management"

# 打包（注意：包含 dist/，排除 node_modules、pgdata、server/data、本地 .env、.git、electron）
Compress-Archive -Path `
  package.json, package-lock.json, knexfile.js, vite.config.ts, `
  tsconfig.json, tsconfig.node.json, postcss.config.js, tailwind.config.js, `
  index.html, docker-compose.yml, `
  src, server, scripts, dist, `
  .env.production `
  -DestinationPath "case-management-v1.1.zip" -Force
```

> **不要打进 zip**：`node_modules`、`pgdata`、`server/data`、`.env`、`.git`、`electron`、`dist-exe`、`_pack`。
> **必须打进**：`dist/`（前端构建产物）、`server/`（后端代码 + migrations）、`scripts/`（含 `wait-pg.js`）、`docker-compose.yml`、`.env.production`。

### 2.4 上传到中转

任选一个把 `case-management-v1.1.zip` 传上去，拿到一个能直接 `wget` 的 URL：

- **catbox.moe**（最快，免登录，但有时墙）：拖文件到 https://catbox.moe/，复制返回的链接
- **阿里云 OSS**（用户已有阿里云）：传 OSS bucket，临时签名 URL
- **GitHub release**（如果代码有 GitHub repo）：在 release 上传 zip

## 三、服务器：首次部署 v1.1（完整流程）

> **前提说明**：v1.0 服务器上现有数据全部是测试数据，本流程直接清空 `/opt/case-management` 整个目录从零开始。**不做备份**——如未来部署时数据已是生产数据，请先按第五章备份再回到这一章。

### 3.1 清掉 v1.0、准备空目录

```bash
ssh <<请填写：SSH 用户>>@<<请填写：服务器 IP 或域名>>

# 停掉 v1.0 进程
pm2 stop case-mgmt 2>/dev/null || true
pm2 delete case-mgmt 2>/dev/null || true

# 整个目录清空（含旧 SQLite、旧 .env、旧附件）
rm -rf /opt/case-management
mkdir -p /opt/case-management
cd /opt/case-management
```

### 3.2 拉取 + 解压新版

```bash
cd /opt/case-management

wget -O v1.1.zip "<上面 2.4 拿到的 URL>"
unzip v1.1.zip
rm v1.1.zip

# .env.production 是部署用的配置模板，重命名为 .env 让 dotenv 加载
mv .env.production .env
```

### 3.3 装依赖（生产用，不装 devDeps）

```bash
cd /opt/case-management
npm install --omit=dev --no-audit --no-fund
```

> 服务器装依赖比本地慢且占内存。建议先 `free -h`，如果 available 内存不足 1G，开个 swap：
> ```bash
> fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
> ```

### 3.4 启动 PostgreSQL 容器

```bash
cd /opt/case-management
npm run db:up   # 等价于 docker compose up -d postgres
```

第一次会拉 `postgres:16-alpine` 镜像（约 80MB）。等 30 秒~1 分钟，用以下命令确认 PG 跑起来了：

```bash
docker ps | grep case-pg                  # 应看到 case-pg 容器 (healthy)
docker logs case-pg --tail 20             # 没有 ERROR 行
node scripts/wait-pg.js                   # "PostgreSQL is ready" 才算成功
```

数据持久化在 `/opt/case-management/pgdata/`。**这个目录是数据库本体，备份它 + .env 就等于备份整个系统的元数据。**

### 3.5 跑 migration + seed

```bash
npm run db:migrate    # 跑 001~010 全部 migration（建 users、cases、case_reviews、pipelines 等表）
npm run db:seed       # 用 .env 里的 ADMIN_* 创建第一个 admin 账号
```

migrate 输出应该看到 `Batch 1 run: 10 migrations`（v1.1 当前共 10 条）。

### 3.6 启动 Express

```bash
cd /opt/case-management
pm2 start server/index.js --name case-mgmt
pm2 save                          # 保存进程列表，开机自动恢复
pm2 startup                       # 第一次执行的话，按提示再跑一行
pm2 status case-mgmt              # 应是 "online"
pm2 logs case-mgmt --lines 30     # 看启动日志，应有 "API listening on :4000"
```

### 3.7 nginx 反代（首次部署，已配置过的跳过）

`/etc/nginx/sites-available/case-management`：
```nginx
server {
  listen 80;
  server_name <<请填写：服务器 IP 或域名>>;

  client_max_body_size 30M;       # 合同 / 附件上传上限

  location / {
    proxy_pass http://127.0.0.1:4000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 300s;        # AI 审核可能耗时较长
    proxy_send_timeout 300s;
  }
}
```

```bash
ln -sf /etc/nginx/sites-available/case-management /etc/nginx/sites-enabled/
nginx -t                          # 配置语法检查
systemctl reload nginx
```

### 3.8 验证

浏览器打开 `http://<<请填写：服务器 IP 或域名>>/`：
- 能看到登录页 → 后端进程 + nginx 都通了
- 用 `.env` 里的 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录 → seed 跑通了
- 进「系统设置」→ 填 OpenAI Key（如果 .env 里已填可跳过，里面会显示 `sk-t***xxxx` mask）→ 测连通性
- 进「审核模型」→ 应有出厂的"通用合同审核"和"劳动合同审核"两条
- 上传一份 .docx 测试合同审核（**实测一次，端到端确认**）

## 四、后续更新（v1.1 → v1.1.x）

第二次起，流程极简（**前提：不动 .env、不动 pgdata、不动 server/data**）：

```bash
# 本地
npm run build
Compress-Archive ... -DestinationPath "case-management-v1.1.x.zip" -Force
# 上传到中转，拿 URL

# 服务器
ssh <<请填写：SSH 用户>>@<<请填写：服务器 IP 或域名>>
cd /opt/case-management

# 备份当前代码 (不带 pgdata / server/data / .env)
tar czf /tmp/before-update-$(date +%Y%m%d-%H%M%S).tar.gz \
  --exclude=pgdata --exclude=server/data --exclude=node_modules \
  src server scripts dist

# 清掉旧代码（保留 .env、pgdata、server/data、node_modules）
rm -rf src server scripts dist
rm -f package.json package-lock.json knexfile.js vite.config.ts tsconfig*.json
rm -f postcss.config.js tailwind.config.js index.html docker-compose.yml

# 拉新版
wget -O v1.1.x.zip "<新 zip URL>"
unzip v1.1.x.zip
rm v1.1.x.zip

# 装新依赖（如果有变化）
npm install --omit=dev --no-audit --no-fund

# 跑可能新增的 migration（已跑过的会自动 skip）
npm run db:migrate

# pm2 平滑重启
pm2 reload case-mgmt
pm2 logs case-mgmt --lines 30
```

## 五、备份策略

每周 / 每次重大变更前各跑一次：

```bash
# 1) PG 数据库逻辑备份（推荐，可跨机器恢复）
docker exec case-pg pg_dump -U case_mgmt case_mgmt | gzip > /opt/backup/db-$(date +%Y%m%d).sql.gz

# 2) PG 数据目录物理备份（要先停容器才能拷贝一致状态）
docker compose down
tar czf /opt/backup/pgdata-$(date +%Y%m%d).tar.gz pgdata/
docker compose up -d postgres

# 3) 文件存储（合同原件、修订版、消息附件）
tar czf /opt/backup/files-$(date +%Y%m%d).tar.gz server/data/

# 4) .env （含密码 / Key，单独安全保管）
cp .env /opt/backup/env-$(date +%Y%m%d).bak
```

可以做成 cron 定时任务：`crontab -e` 加一行
```
0 3 * * * cd /opt/case-management && docker exec case-pg pg_dump -U case_mgmt case_mgmt | gzip > /opt/backup/db-$(date +\%Y\%m\%d).sql.gz
```

## 六、常见问题排错

| 现象 | 原因 / 排查 |
|---|---|
| `npm run db:up` 失败 / 容器起不来 | `systemctl status docker` 看 Docker 是否在跑；`docker logs case-pg` 看 PG 报错；端口 5432 被占用？`lsof -i :5432` |
| `npm run db:migrate` 报 connect ECONNREFUSED | PG 还没就绪，先跑 `node scripts/wait-pg.js`；或 `.env` 的 `DATABASE_URL` 密码与 `PG_PASSWORD` 不一致 |
| 登录后调任意 API 报 500 | `pm2 logs case-mgmt`，看是否 PG 连接异常 / migration 没跑全 |
| AI 审核一直转圈 / 报 401 | 系统设置的 OpenAI Key 没配 / 错；`.env` 的 OPENAI_API_KEY 也是 sk-replace-me |
| 上传文件失败、500 | `client_max_body_size`（nginx）和 `UPLOAD_MAX_BYTES`（.env）都要 ≥ 20MB |
| 法务上传修订版后业务方没收到消息 | 看 `audit_logs.payload` 里 `notifyError` 字段（v1.1 已加）；常见原因：业务方账号被删 |
| 80 端口打不开 | 阿里云控制台安全组放行 80；`nginx -t` + `systemctl status nginx`；`pm2 status case-mgmt` 看 Express 是否 online |
| Express 起不来报端口被占 | 改 `.env` 的 `PORT`（默认 4000，别用 3000），同步改 nginx `proxy_pass` 端口 |

日志位置速查：
- pm2: `~/.pm2/logs/case-mgmt-out.log` / `case-mgmt-error.log`，或 `pm2 logs case-mgmt`
- PG 容器: `docker logs case-pg`
- nginx: `/var/log/nginx/error.log` / `access.log`

## 七、关键命令速查

| 操作 | 命令 |
|---|---|
| 启 PG 容器 | `npm run db:up` |
| 停 PG 容器 | `npm run db:down` |
| 跑迁移 | `npm run db:migrate` |
| 回滚一步迁移 | `npm run db:rollback` |
| seed admin | `npm run db:seed` |
| 启动 Express（首次） | `pm2 start server/index.js --name case-mgmt` |
| 平滑重启 Express | `pm2 reload case-mgmt` |
| 查应用日志 | `pm2 logs case-mgmt --lines 100` |
| 查 PG 日志 | `docker logs case-pg --tail 100` |
| 进 PG 终端 | `docker exec -it case-pg psql -U case_mgmt -d case_mgmt` |
| nginx 重载 | `nginx -t && systemctl reload nginx` |

## 八、本手册待实测项

> 这份手册基于代码现状写就，**完整端到端流程未亲跑过**。第一次按照本文档部署时，请重点验证：

1. **第二章 Compress-Archive 命令**：参数列表是否漏文件 / 多文件，PowerShell 是否能直接跑通
2. **第三章 3.4 PG 启动**：阿里云海外节点拉 docker.io 镜像速度够不够，是否需要切到 daocloud 镜像
3. **第三章 3.6 pm2 startup**：在用户的 Ubuntu 版本下首次执行可能会输出一行需手动复制的命令
4. **第四章后续更新流程**：v1.1.0 → v1.1.x 时旧 server/data 不动是否真能保持合同附件不丢
5. **第五章备份脚本**：`docker exec case-pg pg_dump` 在容器名字为 `case-pg` 时能跑通

跑过一遍后把发现的偏差补回这份文档。
