# 案件管理系统 测试版 v1.0

> 发布日期：2026-04-22
> 部署环境：阿里云轻量服务器（海外节点）·  Ubuntu · Node 20.20.2 · pm2 · nginx
> 访问入口：`http://8.217.237.3/`

---

## 一、版本定位

- **测试版（pilot）**：面向天弘矿业法务团队 3-5 名律师小范围试用
- **目标**：验证 Web 化后的核心录入 / 检索 / 协作流程，收集功能与体验反馈
- **本版本不承诺数据持久性 SLA**：上线初期建议每周手动备份一次 SQLite 文件

## 二、已上线功能清单

### 1. 账户与认证
| 功能 | 说明 |
|---|---|
| 账号密码登录 | JWT 7 天有效期，过期自动跳登录页 |
| 修改密码 | 个人设置入口，需输入当前密码 |
| 首次自动种子管理员 | 首次启动时按 `.env` 中的 `ADMIN_USERNAME / ADMIN_PASSWORD` 创建唯一 admin |

### 2. 用户管理（仅管理员可见）
| 功能 | 约束 |
|---|---|
| 查看全部用户 | 按创建时间倒序 |
| 新增用户 | 账号 2-32 字符；密码 ≥ 6 位；可设角色 admin / user |
| 删除用户 | 不能删除自己；不能删除"最后一个管理员" |
| 重置任意用户密码 | 新密码 ≥ 6 位 |

### 3. 案件录入与维护
- **30+ 字段**覆盖：案件编号、案由、争议类型、阶段、双方主体、第三人、对方代理人/律所、涉案金额（万元）、6 个时间节点、争议焦点、我方诉求、当前进展、判决结果、执行进展、复盘要点、备注 等
- **必填字段**：案件编号、案件名称、案由、争议类型、案件阶段、我方主体、对方主体、当前进展
- **结案方式**在阶段为「执行」或「结案」时强制必填
- 抽屉式编辑界面（不离开列表）

### 4. 案件检索与展示
- 顶部统计卡片：全部 / 进行中 / 已结案 / 7 天内有节点
- 多条件筛选（案由、阶段、关键字等）
- 表格分页 / 排序
- 案件详情抽屉（只读视图）
- 批量勾选

### 5. 数据导入 / 导出
- **批量导入**（JSON / 纯文本，三种合并模式）
  - `append`：追加，遇到重复案号跳过
  - `replace`：清空后导入
  - `renumber`：自动用「暂时01、暂时02」编号
- **导出 TXT**：按当前筛选结果或勾选项导出

### 6. AI 智能录入（亮点功能）
- 上传 **PDF / Word（.docx / .doc）** 案件材料
- 选择"我方身份"（原告 or 被告），AI 据此正确填充我方/对方
- 自动抽取后弹出表单供律师**人工核对再保存**（不会绕过审核直接入库）
- 支持模型：`gpt-5-mini`（默认推荐）/ `gpt-4o` / `gpt-4o-mini` / `o3-mini`
- 支持自定义 baseURL（兼容国内代理服务）

### 7. 系统设置
- OpenAI API Key、baseURL、默认模型
- **存储位置**：用户浏览器 localStorage，**每个浏览器各自配置**，互不可见，服务器零知情

## 三、技术架构

```
┌──────────────────────────────────────────────────────┐
│  律师浏览器                                           │
│  ┌──────────────────────────────────────────────┐    │
│  │ React 18 + Vite + TS + Tailwind + zustand    │    │
│  │   ├─ JWT token（localStorage）                │    │
│  │   └─ OpenAI Key（localStorage，仅本地）       │    │
│  └────┬───────────────────────────┬─────────────┘    │
└───────┼───────────────────────────┼──────────────────┘
        │ HTTPS                     │ HTTPS（仅 AI 抽取）
        ▼                           ▼
┌─────────────────────────┐   ┌─────────────────────┐
│  nginx (80)             │   │  api.openai.com     │
│   └─ proxy → 127.0.0.1: │   └─────────────────────┘
│             4000        │
└────────┬────────────────┘
         ▼
┌─────────────────────────────────────────┐
│  Express 4 + better-sqlite3（pm2 守护）  │
│   ├─ /api/auth/*    JWT + bcrypt        │
│   ├─ /api/users/*   admin only          │
│   ├─ /api/cases/*   CRUD + bulk-import  │
│   └─ /          serve dist/（SPA）       │
└────────┬────────────────────────────────┘
         ▼
   server/data/app.db
   （SQLite WAL 模式 · 单文件）
```

### 关键技术决策
| 选择 | 原因 |
|---|---|
| 单进程 Express 同时 serve 前后端 | 无跨域、单端口、运维简单 |
| SQLite + WAL | 单机 3-5 用户场景下零运维，性能足够 |
| AI 抽取在浏览器直连 OpenAI | 服务器不接触用户 key、不留存案件原始材料 |
| 端口 4000 | 避开 Windows 动态保留段（3000 在 Windows 上可能被占） |
| Express 锁 4.x | Express 5 + 高版本 Node 有 `app.listen` 进程秒退 bug |

## 四、本版本已知限制

### 🔴 重要（建议下个版本修复）
1. **多人编辑可能静默覆盖**
   - 同一案件被两人前后保存时，后保存者会覆盖前者所有字段
   - 没有版本号校验、没有冲突提示
   - **临时规避**：协调律师不要同时编辑同一案件
2. **列表不实时刷新**
   - 登录后只拉取一次案件列表，他人修改不会自动同步
   - **临时规避**：刷新页面（F5）查看最新数据
3. **案件编号无唯一约束**
   - 数据库层未阻止重复 `caseNumber`
   - 单条新增不去重，仅 `bulk-import append` 模式去重

### 🟡 一般
4. **无操作审计日志**：谁什么时候改了什么字段，目前无记录
5. **不留存案件原始材料**：AI 抽取后 PDF/DOCX 用完即弃，需要的话请律师自行归档
6. **无自动备份**：SQLite 文件需要运维手动备份
7. **bulk-import 请求体上限 2MB**：超大批量需分批

### 🟢 已知不修
8. **API Key 存浏览器 localStorage**：架构选型，每用户独立 key 的代价
9. **AI 抽取需用户网络能直连 OpenAI**：服务器在海外节点对此有利，但用户浏览器仍需自身网络可达；不可达时改 baseURL 走国内兼容服务

## 五、运维快速参考

> **完整部署流程**详见 `docs/部署手册.md`（如未生成，参见会话记录）

### 日常巡检
```bash
pm2 status case-mgmt                  # 查看进程状态
pm2 logs case-mgmt --lines 100        # 查看日志
curl http://127.0.0.1:4000/api/health # 健康检查
```

### 重启服务
```bash
pm2 restart case-mgmt                 # 重启
pm2 reload case-mgmt --update-env     # 零停机重载（推荐）
```

### 备份数据库
```bash
# 推荐每天凌晨自动跑（cron）
cp /opt/case-management/server/data/app.db \
   /opt/case-management/backups/app.db.$(date +%Y%m%d)
```

### 故障排查
| 现象 | 排查方向 |
|---|---|
| 页面打不开 | `nginx -t` / `systemctl status nginx` / 阿里云防火墙 80 端口 |
| 502 Bad Gateway | `pm2 status` 看进程是否在；`ss -tlnp \| grep 4000` |
| 登录报 500 | `pm2 logs case-mgmt`，多半是 DB 文件权限或环境变量缺失 |
| AI 抽取报错 | 浏览器 F12 看网络请求；多半是 API Key 错或 OpenAI 不通 |

## 六、测试建议（给试用律师）

### 优先验证
- [ ] 登录、改密码
- [ ] 新增 1-2 个真实案件，覆盖原告 / 被告两种身份
- [ ] AI 智能录入：上传一份起诉状 PDF，验证字段抽取准确度
- [ ] 案件编辑、归档、删除
- [ ] 批量导入（先用 3-5 条试水，再考虑大批量）
- [ ] 导出 TXT，对比内容完整性
- [ ] 多条件筛选与排序

### 重点反馈
- 字段命名 / 顺序 / 必填规则是否贴合实际工作习惯
- AI 抽取的准确率 & 哪些字段最常错
- 批量导入的格式约定是否清晰
- 对"多人协作"是否有强需求（决定下个版本要不要优先做冲突防护）

### 已知不要测试的场景
- 两人同时编辑同一案件（**会丢数据**，留待 v1.1 修复）
- 上传单个 > 20MB 的 PDF（OpenAI 限额）
- 关闭浏览器换电脑后不重新填 OpenAI Key（设置不跨设备同步）
