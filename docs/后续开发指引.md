## 3. 核心代码导读

### 3.1 类型系统（`src/types/index.ts`）

这是整个系统的数据契约，所有开发都从这里出发。

```
CaseRecord       → 案件主实体（完整字段）
CaseFilters      → 筛选条件状态
PaginationState  → 分页状态
SortState        → 排序状态
UserContext      → 用户/权限（预留，未实现）
OperationLog     → 操作日志（预留，未实现）
CaseAttachment   → 附件（预留，未实现）
CaseComment      → 评论（预留，未实现）
```

**修改原则**：添加新字段时先在 `CaseRecord` 中定义类型，TypeScript 编译错误会自动指引你找到所有需要同步修改的地方。

### 3.2 状态管理（`src/store/useCaseStore.ts`）

使用 Zustand 管理全局状态。结构分为：

```ts
// Store 读取
const { cases, filters, pagination } = useCaseStore()

// Store 写入（action）
const { addCase, updateCase, deleteCase } = useCaseStore()

// 衍生选择器（避免全量订阅）
const cases = usePaginatedCases()     // 当前页数据
const c = useCaseById(id)             // 单条数据
const stats = useCaseStats()          // 统计数字
```

**注意**：每次修改数据后都会调用 `_recompute()` 重新计算 `filteredCases`，这是筛选和排序的统一入口。接入 API 后，`_recompute` 应改为触发 API 请求。

### 3.3 筛选逻辑（`src/utils/helpers.ts`）

`applyFilters(cases, filters)` 函数实现了前端所有筛选逻辑，是一个纯函数（无副作用），便于测试。接入后端后，这个函数应被删除或仅保留作为本地缓存筛选使用，筛选参数应传至后端 API。

### 3.4 颜色配置（`src/constants/index.ts`）

Badge 颜色通过以下对象集中配置，用 Tailwind 类名字符串表示：

```ts
DISPUTE_TYPE_BADGE[type]  // 争议类型 Badge 颜色
CASE_STAGE_BADGE[stage]   // 案件阶段 Badge 颜色
URGENCY_BADGE[level]      // 截止日期紧迫度颜色
URGENCY_TEXT_COLOR[level] // 紧迫度文字颜色
```

修改颜色只需修改这里，组件会自动应用。

## 6. 如何接入后端 API

当前所有数据操作在 `src/store/useCaseStore.ts` 的 action 中完成。接入后端时，改造这里即可，UI 层无需修改。

### 推荐方案：封装 API 层

**第一步：创建 API 请求层**

```ts
// src/api/cases.ts

const BASE_URL = import.meta.env.VITE_API_URL || 'http://localhost:8080/api'

const headers = () => ({
  'Content-Type': 'application/json',
  'Authorization': `Bearer ${localStorage.getItem('token') ?? ''}`,
})

export const casesApi = {
  list: (params: CaseFilters & PaginationState) =>
    fetch(`${BASE_URL}/cases?${new URLSearchParams(params as any)}`, { headers: headers() })
      .then(r => r.json()),

  getById: (id: string) =>
    fetch(`${BASE_URL}/cases/${id}`, { headers: headers() }).then(r => r.json()),

  create: (data: Partial<CaseRecord>) =>
    fetch(`${BASE_URL}/cases`, {
      method: 'POST',
      headers: headers(),
      body: JSON.stringify(data),
    }).then(r => r.json()),

  update: (id: string, data: Partial<CaseRecord>) =>
    fetch(`${BASE_URL}/cases/${id}`, {
      method: 'PATCH',
      headers: headers(),
      body: JSON.stringify(data),
    }).then(r => r.json()),

  delete: (id: string) =>
    fetch(`${BASE_URL}/cases/${id}`, { method: 'DELETE', headers: headers() }),

  archive: (id: string) =>
    fetch(`${BASE_URL}/cases/${id}/archive`, { method: 'POST', headers: headers() }).then(r => r.json()),
}
```

**第二步：改造 Zustand Store**

将 action 中的本地数组操作替换为 API 调用：

```ts
// src/store/useCaseStore.ts（改造后的 addCase 示例）
addCase: async (data) => {
  set({ isLoading: true })
  try {
    const newCase = await casesApi.create(data)
    set(s => ({ cases: [newCase, ...s.cases], isLoading: false }))
    get()._recompute()
  } catch (err) {
    set({ isLoading: false, error: String(err) })
  }
},
```

**第三步：改造筛选逻辑（服务端筛选）**

当前 `_recompute` 在前端筛选。接入后端后，改为在 `setFilters` 时触发 API 请求：

```ts
setFilters: async (filters) => {
  set(s => ({ filters: { ...s.filters, ...filters }, pagination: { ...s.pagination, page: 1 } }))
  // 触发后端查询（替代前端 applyFilters）
  await get()._fetchFromServer()
},

_fetchFromServer: async () => {
  const { filters, pagination, sort } = get()
  set({ isLoading: true })
  const result = await casesApi.list({ ...filters, ...pagination, ...sort })
  set({
    filteredCases: result.items,
    totalCount: result.total,
    isLoading: false,
  })
},
```

**第四步：配置环境变量**

```bash
# .env.development
VITE_API_URL=http://localhost:8080/api

# .env.production
VITE_API_URL=https://your-production-domain.com/api
```

> **注意**：`.env` 文件不要提交到 Git，在 `.gitignore` 中添加。

### 后端 API 接口建议规范

```
GET    /api/cases              # 列表（支持 query params 筛选）
POST   /api/cases              # 创建
GET    /api/cases/:id          # 详情
PATCH  /api/cases/:id          # 更新（部分字段）
DELETE /api/cases/:id          # 删除
POST   /api/cases/:id/archive  # 归档
POST   /api/cases/:id/unarchive # 取消归档

# 未来扩展

GET    /api/cases/:id/comments       # 评论列表

```

## 7. 如何接入权限系统

类型文件中已预留 `UserContext` 接口：

```ts
// src/types/index.ts
interface UserContext {
  id: string
  name: string
  role: 'admin' | 'lawyer' | 'viewer'
  department: string
}
```

### 推荐实现步骤

**第一步：创建 Auth Store**

```ts
// src/store/useAuthStore.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'   // 持久化到 localStorage

interface AuthState {
  user: UserContext | null
  token: string | null
  isLoading: boolean
  login: (username: string, password: string) => Promise<void>
  logout: () => void
  isAdmin: () => boolean
  hasPermission: (action: string) => boolean
}

export const useAuthStore = create<AuthState>()(
  persist(
    (set, get) => ({
      user: null,
      token: null,
      isLoading: false,
      login: async (username, password) => {
        set({ isLoading: true })
        const res = await fetch('/api/auth/login', {
          method: 'POST',
          body: JSON.stringify({ username, password }),
        }).then(r => r.json())
        set({ user: res.user, token: res.token, isLoading: false })
      },
      logout: () => set({ user: null, token: null }),
      isAdmin: () => get().user?.role === 'admin',
      hasPermission: (action) => {
        const role = get().user?.role
        // 定义权限规则
        const rules: Record<string, string[]> = {
          'case:delete': ['admin'],
          'case:archive': ['admin', 'lawyer'],
          'case:create': ['admin', 'lawyer'],
          'case:edit': ['admin', 'lawyer'],
          'case:view': ['admin', 'lawyer', 'viewer'],
        }
        return rules[action]?.includes(role ?? '') ?? false
      },
    }),
    { name: 'auth-store' }
  )
)
```

**第二步：在组件中使用权限判断**

```tsx
// 示例：隐藏删除按钮（仅 admin 可见）
const { hasPermission } = useAuthStore()

{hasPermission('case:delete') && (
  <Button variant="ghost" size="sm" onClick={() => setDeleteConfirm(true)}>
    <Trash2 size={13} />
  </Button>
)}
```

**第三步：添加路由守卫**

```tsx
// src/components/layout/AuthGuard.tsx
import { Navigate } from 'react-router-dom'
import { useAuthStore } from '@/store/useAuthStore'

export function AuthGuard({ children }: { children: React.ReactNode }) {
  const { user } = useAuthStore()
  if (!user) return <Navigate to="/login" replace />
  return <>{children}</>
}
```

### 8.3 节点提醒

实现建议（前端侧）：

1. **浏览器通知**：用户授权后，可使用 Web Notifications API 发送本地提醒
2. **邮件提醒**：后端定时任务（cron job）扫描 `reminderDate` 字段，当天发送邮件
3. **消息中心**：在顶部导航栏添加铃铛图标 + 未读数字，点击展示提醒列表

```ts
// 后端 cron job 伪代码（Node.js + node-cron）
cron.schedule('0 8 * * *', async () => {    // 每天早 8 点
  const today = new Date().toISOString().slice(0, 10)
  const cases = await db.cases.findMany({
    where: { reminderDate: today, isArchived: false }
  })
  for (const c of cases) {
    await sendEmail({
      to: c.assignedLawyerEmail,
      subject: `【案件提醒】${c.caseName} - ${c.nextKeyDateLabel}`,
      body: `案件 ${c.caseNumber} 的关键节点「${c.nextKeyDateLabel}」将于 ${c.nextKeyDate} 到来，请注意跟进。`
    })
  }
})
```

### 8.6 数据统计页

建议使用 `recharts` 或 `echarts-for-react`，推荐图表：

- 饼图：争议类型分布
- 柱状图：各阶段案件数量
- 折线图：近 12 个月新增案件趋势
- 数字卡片：涉案金额合计、已回款金额合计
- 律师工作量排行：每位律师负责的案件数和涉案金额

### 8.7 导出 Excel

推荐使用 `exceljs` 或 `xlsx` 库：

```ts
// src/utils/exportCases.ts
import ExcelJS from 'exceljs'

export async function exportCasesToExcel(cases: CaseRecord[]) {
  const workbook = new ExcelJS.Workbook()
  const sheet = workbook.addWorksheet('案件台账')

  // 设置表头
  sheet.columns = [
    { header: '案件编号', key: 'caseNumber', width: 15 },
    { header: '案件名称', key: 'caseName', width: 40 },
    { header: '争议类型', key: 'disputeType', width: 12 },
    // ...
  ]

  // 填充数据
  cases.forEach(c => sheet.addRow({
    caseNumber: c.caseNumber,
    caseName: c.caseName,
    disputeType: DISPUTE_TYPE_LABELS[c.disputeType],
    // ...
  }))

  // 下载
  const buffer = await workbook.xlsx.writeBuffer()
  const blob = new Blob([buffer], { type: 'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet' })
  const url = URL.createObjectURL(blob)
  const link = document.createElement('a')
  link.href = url
  link.download = `案件台账_${new Date().toLocaleDateString('zh-CN')}.xlsx`
  link.click()
}
```

## 10. 代码规范与注意事项

### TypeScript

1. **不要使用 `any`**，除非在接入第三方未提供类型的库时临时使用，用 `// TODO: type this` 注释标记
2. 所有新接口定义统一放在 `src/types/index.ts`，不要在组件文件内定义业务类型
3. 组件 Props 类型直接定义在组件文件内（非业务数据），用 `interface` 而非 `type`

### 组件规范

1. **UI 组件**（`src/components/ui/`）：不引用 Store，只通过 Props 接受数据和回调，保持纯粹
2. **业务组件**（`src/components/cases/`）：可以直接调用 `useCaseStore()`
3. **页面**（`src/pages/`）：负责组合业务组件，不编写具体业务逻辑
4. 所有组件文件使用 `.tsx` 扩展名

### 样式规范

1. **优先使用 Tailwind 工具类**，不建议新增自定义 CSS，除非是动画等 Tailwind 无法覆盖的场景
2. 颜色值不要硬编码在组件里，统一通过 `src/constants/index.ts` 中的配置对象引用
3. 需要条件组合 className 时，使用 `cn()` 工具函数（来自 `src/utils/helpers.ts`）
4. 禁止使用内联 `style` 属性，除非是动态计算的值（如 `{ width: percentage + '%' }`）

### 状态管理

1. **不要在组件内用 `useState` 管理跨组件共享状态**，统一放 Zustand Store
2. 各组件内的 UI 状态（如弹窗开关、hover 状态）可以继续用 `useState`
3. Store 中的 action 命名规范：动词 + 名词（`addCase`、`updateCase`、`setFilters`）
4. 接入 API 后，考虑引入 `TanStack Query`（React Query）管理服务器状态，Zustand 只保留 UI 状态

### Git 提交规范（推荐）

```
feat: 新增案件评论功能
fix:  修复筛选面板金额区间边界值问题
refactor: 重构 CaseTable 为独立 CaseRow 组件
style: 调整详情抽屉间距
docs: 更新开发文档
```

### 安全注意事项

1. **API 密钥、数据库连接字符串**不要写在前端代码中，统一通过 `.env` 文件管理
2. `.env` 文件不要提交到 Git（`.gitignore` 中已排除）
3. 接入后端后，所有写操作（增删改）都要在服务端做权限校验，不能只依赖前端隐藏按钮
4. 用户输入的内容在展示时 React 已自动 escape，无需手动处理 XSS
5. 接入文件上传时，后端必须校验文件类型和大小，不能只做前端验证
